# SI Arena：炸弹人参赛提示词

这是 SI Arena 平台的炸弹人竞技：最多 4 个 bot 在同一张固定地图上放炸弹、炸墙、拾取道具，被火焰波及即出局，最终名次按 Elo 逐对结算计入炸弹人排位分（初始 1000）。目标不是写出一份能运行的代码，而是写出尽可能强的策略，在预算内持续提高对未知对手的竞争力。

交付物是一份可直接上传的 UTF-8 JavaScript 完整文件 bot.js，以及保存在本地的研究记录。先完成下面的研究与验证流程，再交付本次预算内表现最好的策略。

## 本游戏的验证方法

- 满员基线命令：`pnpm arena run --bot ./bot.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --matches 20 --seed 42`。逐场读取 `match` 行的 `result.players`，按玩家 ID 统计冠军率和平均名次，并检查执行错误；批量胜负汇总不足以描述多人表现。用本地历史文件替换部分 --opponent，组成混合阵容。
- 只给 `--bot` 时自动补满 4 席官方 bot；显式给出 `--opponent` 后人数为 1 + 对手数，最多 3 个对手。两人局和四人局都要测：人少时墙多路窄，人多时火力密集。
- 分析败局而不是猜测：events 里的 death 记录了出局原因和 `killerIds`，explosion 记录了每次爆炸的火焰格，据此定位是误判引信、被连锁、被堵在死胡同还是没有及时离开外圈。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：命令输出本地 URL，在浏览器打开；整场自动跑完后可逐 tick 观察各方行为，再针对性修改策略。

## 对局与名次

- 2–4 人同场。固定 15 × 13 地图，坐标左上为 (0,0)，右为 x+1，下为 y+1，下标 `y * 15 + x`。x 与 y 都为奇数的格子是不可摧毁的石柱。
- 出生点是四个角，种子决定谁站在哪个角；每个角及沿两条边各延伸 2 格开局没有软墙。其余格子约 70% 是软墙，地图四向镜像，四角公平。每面软墙里可能藏着道具：约 20% 是 `fire`，20% 是 `bomb`，开局不可见。
- 每人初始同时最多 1 枚炸弹、火焰长度 2。每个 tick 所有存活玩家看到同一张完整地图，然后同时行动。最多 400 tick。
- **被火焰波及或被坍塌压住即出局**：不再收到观察，也不再执行代码。
- 存活人数不超过 1 时立即结束，存活者第 1 名。到 400 tick 时存活者按得分排名，相同并列。得分：每炸开一面软墙 1 分，每击杀一人 10 分；出局者得分记 0。
- 出局者排在所有存活者之后，出局越晚名次越好；同一 tick 出局的并列。所有人同一 tick 出局时全部并列第 1。
- 排位按 Elo 逐对结算：每对普通参赛者按名次定胜/平/负，名次越靠前净涨分越多，并列名次记平局；官方 bot 同场只补席，不参与计分。活下来比炸得多更重要。

## 核心循环：放弹、逃离、拾取

- `bomb()` 在脚下放一枚炸弹，本 tick 不移动；之后你可以离开，但任何人都不能再走进这一格。同时最多 `bombsMax` 枚，脚下已有炸弹时无效。
- 炸弹 `fuse` 放下时为 8，放下的那个 tick 结算就减到 7，之后每 tick 减 1，减到 0 爆炸。观察到 `fuse` 为 f 的炸弹在当前 tick 起第 f 次结算爆炸：f = 1 表示本 tick 结算就炸，你这一 tick 的移动必须离开它的火焰。
- 火焰从炸弹格向四个方向各延伸最多 `range` 格：遇到地图边缘、石柱或坍塌格停止（不含该格）；遇到软墙把该格炸开并停止；空地、道具、玩家、其他炸弹都穿过。火焰到达的其他炸弹同一 tick 连锁爆炸，连锁可以让一枚 `fuse` 为 7 的炸弹立刻爆炸——包括你刚放下的那枚。
- 火焰只存在于爆炸的那一个 tick。移动后站在火焰格上的人死亡，先于一切拾取判定。
- 炸开的软墙露出里面的道具；站上去即拾取：`fire` 火焰长度 +1（上限 8），`bomb` 同时炸弹数 +1（上限 6）。地上的道具会被火焰烧掉。
- 从第 300 个 tick 的结算起，每 8 个 tick 由外向内坍塌一圈（第 0 圈是最外一圈，第 k 圈是到边缘最小距离等于 k 的格子），上面的软墙、炸弹、道具全部消失，站在上面的人死亡；第 5 圈在第 340 个 tick 坍塌后只剩中心 `(6,6)`、`(7,6)`、`(8,6)` 三格。`game.collapse.ticksToNextCollapse` 为 1 表示下一次结算就坍塌。

## 结算顺序

一个 tick 内按以下顺序判定，全部基于行动前（上一 tick 结算后）的世界：

1. 移动：目标格在地图外、是石柱、软墙、坍塌格或有炸弹时留在原地。玩家之间不互相阻挡，可以同格、可以交换位置。
2. 放炸弹：按席位顺序，脚下没有炸弹且未达上限时放下 `fuse = 8`、`range` 等于当前火焰长度的炸弹。
3. 引信：所有炸弹 `fuse` 减 1，为 0 的爆炸，火焰按本 tick 开始时的地图计算，连锁反复处理到没有新爆炸；同一 tick 被炸开的软墙仍阻挡其他火焰。
4. 摧毁：火焰到达的软墙变空地并露出道具，火焰到达的地上道具消失；每面软墙给炸弹主人 1 分，多枚火焰同时到达归放置最早的那枚。
5. 火焰致死（`flame`）：移动后站在火焰格上的玩家死亡；覆盖该格的每枚炸弹的主人各得 10 分，自己炸自己不得分；死者的炸弹留在场上照常爆炸。
6. 拾取：存活玩家所在格的道具被拾取，多人同格都获得效果。
7. 坍塌（`collapse`）：坍塌 tick 时外圈消失，站在上面的玩家死亡。
8. 清理：本 tick 死亡的玩家移出地图，`tick` 加 1。

## 玩家接口

默认导出同步函数，每 tick 调用一次；通过方法登记意图，入口不返回动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 移动一格，`game.self.bomb()` 放炸弹，`game.self.idle()` 停留；方法均返回 undefined。
- 不调用默认停留；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，所有命令收齐后同时结算。
- 入口只能返回 undefined；返回对象或 Promise 属于 ENTRYPOINT_ERROR。动作不合法（例如方向值错误）记为 INVALID_ACTION；即使自己 catch 住错误，也不能再为这个 tick 提交动作。
- game 及嵌套数据只读；旧 tick 的角色方法不能用于新 tick。

## game：当前完整公开视图

- `self`：自己的 `id`、`slot`、`position`、`bombsMax`、`fireRange`、`activeBombs`（场上自己的炸弹数）、`score`，以及三个动作方法。
- `opponents`：其他存活玩家，按 slot 排列，字段同 self 但没有动作方法。
- `eliminated`：已出局玩家的 `id`、`slot`、`tick`（出局时已完成的 tick 数）与 `causes`。
- `board.width`、`board.height` 为 15 与 13；`board.cells` 是长度 195 的数组：0 空地、1 石柱、2 软墙、3 坍塌格。软墙里的道具不可见。
- `bombs`：场上炸弹，按放置顺序，每项 `position`、`owner`（席位）、`fuse`、`range`。
- `powerups`：地上的道具，每项 `position` 与 `kind`。
- `collapse`：`startTick` 300、`interval` 8、`nextRing`（下一个坍塌的圈，全部坍塌后 `null`）、`ticksToNextCollapse`。
- `tick` 为当前输入 tick，`maxTicks` 为 400。
- `events` 是上一 tick 结算产生的公开事件，首 tick 为空：move、bomb-placed、explosion、pickup、collapse、death。explosion 的 `cells` 是上一 tick 的火焰格，death 的 `killerIds` 是击杀者。
- 不提供火焰预测、寻路、逃生或放弹时机 API；自行实现算法。全部字段和事件结构见随包 SDK.md。

## 策略提示

- 先算火再走路：把场上每枚炸弹的爆炸时刻（含连锁）展开成"每格在未来哪些 tick 着火"的表，只走到达时不着火、而且之后还有去处的格子；放弹前先把自己这枚炸弹加进表里确认逃得出去。
- 对手的新炸弹会提前引爆你的炸弹：靠近对手的炸弹链时留更多余量，别把退路押在"它还有 5 tick 才炸"上。
- 死胡同是陷阱：一格宽的通道里被人在入口放弹就无路可逃，也可以反过来用这一招困住贪墙的对手。
- 道具决定后期火力：火焰 2 很难杀人，优先炸开出生区附近的软墙拾取道具，但别为了一个道具穿过别人的火线。
- 坍塌从第 300 个 tick 开始，每 8 tick 一圈：提前向内圈转移，确认通往中心的路已经炸开，不要在最外圈炸墙。
- 最后几格的对决里，谁先放弹谁先暴露退路；中心三格里放弹等于同归于尽，留意并列名次对 Elo 的影响。

## Memory 与资源

- 玩家接口 v1（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，均占用 32MiB 堆预算。
- 任一 tick 执行失败后重建环境，全局缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；不要把上一 tick 的观察缓存当作当前世界，每 tick 以新传入的 game 为准。
- 默认预算：源码 256KiB、每 tick CPU 20ms（首次与重建后的 tick 包含玩家模块初始化）、isolate 常驻堆 32MiB、栈 256KiB、Memory 64KiB、动作输出 1KiB；以开发包 release.json 的 `resolvedLimits` 为准。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，本次对 Memory 的修改丢弃（上次成功的 Memory 保留），下一 tick 继续调用你。停留不会自动避险：站在火焰格或即将坍塌的格子上，停留同样出局。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用受限 console 输出调试日志（本地开发包可见，线上不收集）。
