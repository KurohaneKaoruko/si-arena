# SI Arena：圈地大逃杀参赛提示词

这是 SI Arena 平台的大逃杀竞技：最多 5 个 bot 同场，被淘汰即出局，名次换成积分计入大逃杀排行榜。目标不是写出一份能运行的代码，而是写出尽可能强的策略——以稳定活过官方示例 bot 为底线，向排行榜上游竞争。

交付物是一份可直接上传的 UTF-8 JavaScript 完整文件：在开发包项目中工作时，把最终代码写入 bot.js 并完成本地验证；在对话中直接应答时，只输出最终完整代码，不输出 Markdown 围栏或解释。

## 强度标准与验证

- 验收底线：本地与 4 个官方示例 bot 同场打满 20 局（`pnpm arena run --bot ./bot.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --matches 20 --seed 42`），按每场 `match` 行 `result.players` 中的 `rank` 计算，你的平均名次优于官方 bot，且没有任何 tick 执行错误（批量汇总行的胜负只按第 1 名计）；未达标必须继续改进并复测。
- 只给 `--bot` 时对手是 1 个官方 bot（两人局）；每多一个 `--opponent` 多一个对手，最多 4 个。两人局、五人局都要测：地图大小随人数变化。
- 换起始种子复测（如 `--seed 1337`）确认不是种子运气；也可以挂自己的旧版本对弈，避免只针对官方 bot 过拟合。
- 分析败局而不是猜测：events 里的 death 记录了每次出局的原因，trail-cut 记录了切断者，据此定位是外出太贪、安全余量不足、被安全区吞掉还是进攻时机错误。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：命令输出本地 URL，在浏览器打开；整场自动跑完后可逐 tick 观察各方行为，再针对性修改策略。
- 在没有本地环境的对话中使用本提示词时，同样要求按下面的结算顺序逐条推演关键场景（越界、同格、交换、自撞尾迹、被切断、被圈住、安全区）确认动作合法且有竞争力后再输出。

## 对局与名次

- 2–5 人同场。正方形地图，边长 `max(20, ceil(sqrt(320 × 人数)))`：2 人 26、3 人 31、4 人 36、5 人 40。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局各有 3×3 领地，中心格是出生点；出生点等角分布在以地图中心为圆心、半径约 0.32 × 边长的圆上，种子决定起始角和谁站在哪里。
- 每个 tick 所有存活玩家看到同一张完整地图，然后同时行动。最多 800 tick。
- **被淘汰即出局**：领地和尾迹全部变回无主地，不再收到观察，也不再执行代码。
- 存活人数不超过 1 时立即结束，存活者第 1 名。到 800 tick 时存活者按领地格数排名，相同并列。
- 出局者排在所有存活者之后，出局越晚名次越好；同一 tick 出局的并列。所有人同一 tick 出局时全部并列第 1。
- 名次换积分：第 1–5 名分别得 10、6、3、1、0 分，并列者各得该名次的分。活下来比圈得多更重要。

## 核心循环：外出画尾迹，回城圈地

- 头部在自己领地外每移动一格，走过的格子就成为你的尾迹；在外原地停留不延长尾迹。当前位于领地外的头部格也在尾迹里。
- 带着尾迹走进任意一格自己的领地即闭合。尾迹不需要绕成环，两端接上己方领地即可。
- 闭合的判定：把你现有领地和这条尾迹当作屏障，从地图边缘按四邻接洪泛，走不到的格子就是你圈住的格子；其中不是你原有领地的格子是你这次的"圈占"。只被你一人圈占的格子归你，包括别人的领地；同一 tick 被多名闭合者圈占的格子保持原状。
- 圈占的格子上若有别人的尾迹，尾迹的主人出局，即使这个格子因多人争夺没有易手。尾迹压在你原有领地上的人不受影响。
- 闭合后尾迹清空。领地不要求连通，断开的格子照常保留，任何一格己方领地都可以作为回城点。
- 别人圈走你脚下的领地不会让你出局，但你立刻站在领地外，脚下这一格成为你的尾迹，随时可能被切断。
- 领地降为 0 不会出局，但再也无法闭合；只能躲避、切断别人，或等别人先出局。

## 出局判定

一个 tick 内按以下顺序判定，全部基于行动前（上一 tick 结算后）的世界；同一玩家可能同时满足多个原因：

1. 越界（`boundary`）：移动出地图。
2. 撞头：两个及以上头部的目标格相同，全部出局（`head-collision`），包括一方原地停留、被别人走进；两人互换位置，双方出局（`head-swap`）。
3. 切尾迹：目标格是某位存活玩家的尾迹格，该尾迹的主人出局（`trail-cut`），踏入者本身不受影响；即使踏入者本 tick 因撞头出局，切断照样生效。移动进入自己的尾迹也会出局（`self-trail`）；原地停在自己当前头部格不算。
4. 其余玩家移动、留下尾迹。本 tick 新画出的尾迹从下一 tick 起才能被切断。
5. 圈地：见上一节，圈占格上的他人尾迹主人出局（`enclosed`）。
6. 安全区：若本 tick 是缩圈 tick，先缩一圈；之后头部位于安全区外的玩家出局（`zone`）。
7. 本 tick 出局的玩家领地与尾迹全部清空，头部移出地图。

## 安全区

- 安全区是居中的正方形，开局等于整张地图。目标边长 `max(10, ceil(sqrt(320 × 存活人数)))`，有人出局时目标立即变小。
- 当前边长大于目标时，在 tick 编号为 10 的倍数的结算中（第 10、20、30…个 tick）向内收缩一圈（边长减 2），直到不大于目标。是否收缩按该 tick 开始时的存活人数判断。
- 收缩时，落到安全区外的领地和尾迹立即变回无主地；头部留在安全区外的玩家在同一 tick 出局。安全区外的格子永远是无主地，走出去当场出局。
- `game.zone.ticksToNextShrink` 告诉你还要几个 tick 发生下一次收缩（1 表示下一次结算就收缩），不收缩时为 `null`。有人出局后最少只有 1 个 tick 的预警，贴边扩张要留余量。

## 玩家接口

默认导出同步函数，每 tick 调用一次；通过方法登记意图，入口不返回动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 移动一格，`game.self.idle()` 停留；方法均返回 undefined。
- 不调用默认停留；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，所有命令收齐后同时结算。
- 入口只能返回 undefined；返回对象或 Promise 属于 ENTRYPOINT_ERROR。动作不合法（例如方向值错误）记为 INVALID_ACTION；即使自己 catch 住错误，也不能再为这个 tick 提交动作。
- game 及嵌套数据只读；旧 tick 的角色方法不能用于新 tick。

## game：当前完整公开视图

- `self`：自己的 `id`、`slot`、`position`（当前头部坐标）、`spawn`（出生点）、`area`（领地格数），以及两个动作方法。
- `opponents`：其他存活玩家，按 slot 排列，字段同 self 但没有动作方法。
- `eliminated`：已出局玩家的 `id`、`slot`、`tick`（出局时已完成的 tick 数）与 `causes`。
- `board.width`、`board.height` 为地图边长；`board.territory` 与 `board.trails` 是长度 width×height 的数组，下标 `y * width + x`，-1 为无主/无尾迹，0–4 为所属席位。
- `zone`：`size` 当前边长，`target` 目标边长，`min` 左上角格子 `{x, y}`（右下角为 `min + size - 1`），`ticksToNextShrink`。
- `tick` 为当前输入 tick，`maxTicks` 为 800。
- `events` 是上一 tick 结算产生的公开事件，首 tick 为空：move、trail-cut、capture、zone-shrink、death。death 的 causes 给出出局原因。
- 不提供寻路、安全方向、威胁判断或扩张策略 API；自行实现算法。全部字段和事件结构见随包 SDK.md。

## 策略提示

- 一条尾迹是否安全，只取决于你闭合前任何对手能否走到它的任意一格：对每个对手头部做广度优先搜索，比较"对手到达该格的步数"与"你闭合还需要的步数"。
- 五人局里对手多、方向杂，小而快的回环比大回环安全；被逼近时立刻按最短路回城。
- 别人在外画尾迹时，若你能在他回城之前踩到他的任意一格尾迹，就能直接淘汰他，但前提是你自己的尾迹不会先被别人切断。
- 留意别人一旦闭合就会圈占的区域：把尾迹画进去就可能被"圈死"。
- 缩圈时站在外圈的领地会消失；临近 `ticksToNextShrink` 时别在最外圈逗留，也别规划会穿过即将消失格子的回环。

## Memory 与资源

- 当前发行 royale@0.2.0、玩家接口 v1：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，均占用 32MiB 堆预算。
- 任一 tick 执行失败后重建环境，全局缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；不要把上一 tick 的观察缓存当作当前世界，每 tick 以新传入的 game 为准。
- 默认预算：源码 256KiB、每 tick CPU 20ms（首次与重建后的 tick 包含玩家模块初始化）、isolate 常驻堆 32MiB、栈 256KiB、Memory 64KiB、动作输出 1KiB；以开发包 release.json 的 `resolvedLimits` 为准。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，本次对 Memory 的修改丢弃（上次成功的 Memory 保留），下一 tick 继续调用你。停留不会自动避险：站在别人能走到的格子或即将消失的外圈上，停留同样可能出局。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用受限 console 输出调试日志（本地开发包可见，线上不收集）。
