# SI Arena：贪吃蛇大作战参赛提示词

这是 SI Arena 平台的贪吃蛇竞技：最多 4 条蛇同场，死亡即出局，最终名次按 Elo 逐对结算计入贪吃蛇排位分（初始 1000）。目标不是写出一份能运行的代码，而是写出尽可能强的策略，在预算内持续提高对未知对手的竞争力。

交付物是一份可直接上传的 UTF-8 JavaScript 完整文件 bot.js，以及保存在本地的研究记录。先完成下面的研究与验证流程，再交付本次预算内表现最好的策略。

## 本游戏的验证方法

- 满员基线命令：`pnpm arena run --bot ./bot.js --opponent ./bots/official.js --opponent ./bots/official.js --opponent ./bots/official.js --matches 20 --seed 42`。逐场读取 `match` 行的 `result.players`，按玩家 ID 统计冠军率和平均名次，并检查执行错误；批量胜负汇总不足以描述多人表现。用本地历史文件替换部分 --opponent，组成混合阵容。
- 只给 `--bot` 时自动补满 4 席官方 bot（四人局）；给出 `--opponent` 后人数等于 1 + 对手数，最多 3 个对手。两人局（一个 `--opponent ./bots/official.js`）与四人局都要测：地图大小随人数变化。
- 分析败局而不是猜测：events 里的 death 记录了每次出局的原因，据此定位是饿死、追食物撞身、被堵死还是头对头吃亏。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：命令输出本地 URL，在浏览器打开；整场自动跑完后可逐 tick 观察各方行为，再针对性修改策略。

## 对局与名次

- 2–4 条蛇同场。正方形地图，边长 `11 + 2 × 人数`：2 人 15、3 人 17、4 人 19。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局每条蛇 3 节重叠在出生格上，体力 100。出生点为四个角各向内缩 2 格，种子决定谁站在哪个角；左半边的蛇朝右，右半边的蛇朝左。
- 初始食物在地图正中央，以及每条蛇出生点沿 x、y 各向中心移 2 格处各一个。
- 每个 tick 所有存活玩家看到同一张完整地图，然后同时行动。最多 500 tick。
- **死亡即出局**：身体立即移出地图，不再收到观察，也不再执行代码。
- 存活不超过 1 条时立即结束，存活者第 1 名。到 500 tick 时存活者按长度排名，相同并列。
- 出局者排在所有存活者之后，出局越晚名次越好；同一 tick 出局的并列。所有蛇同一 tick 同归于尽时全部并列第 1。
- 排位按 Elo 逐对结算：每对普通参赛者按名次定胜/平/负，名次越靠前净涨分越多，并列名次记平局；官方 bot 同场只补席，不参与计分。活下来比长得长更重要。

## 核心循环：吃食物、省体力、留空间

- 体力每 tick 减 1，吃到食物恢复到 100 并长一节（这一 tick 不去尾）。体力减到 0 的那个 tick 没有吃到食物就饿死，所以每 100 tick 内至少要吃一次。
- 地图上的食物少于存活蛇数（至少 1）时，每 tick 结算末尾随机补一个，另有 15% 几率再补一个。食物只会出现在空格上。
- 蛇不能停留，每 tick 必须前进一格；反向移动会撞进自己的脖子。
- 长度是头对头的筹码：相撞时更短的一方死，相同长度同归于尽。比对手长时可以主动堵路，比对手短时要离对手头部两格以上。

## 出局判定

一个 tick 内按以下顺序结算，全部基于行动前（上一 tick 结算后）的世界；同一条蛇可能同时满足多个原因：

1. 体力：每条存活的蛇体力减 1。
2. 移动：每条蛇在目标格新增头部；目标格上有食物则吃掉它（体力回满、不去尾），否则去掉尾节。多条蛇同时进入同一食物格时都算吃到，再按相撞处理。
3. 死亡判定（对移动后的身体同时判定）：
   - 越界（`boundary`）：目标格在地图外。
   - 饿死（`starvation`）：体力减到 0 且本 tick 没有吃到食物。
   - 撞身（`body-collision`）：头部与任意一条蛇（包括自己）移动后除头部外的任意一节重合。尾节本步移走的格子可以进入；对方本 tick 吃到食物时尾巴不动，进入它就撞上。开局重叠的三节没有展开前，尾巴所在格始终被占用。
   - 头对头（`head-collision`）：头部与另一条蛇的头部同格，长度（含本 tick 的增长）较短者死，相同则都死。
4. 清理：本 tick 死亡的蛇身体全部移出地图。
5. 食物生成：按上一节规则补充食物。
6. tick 加 1；存活不超过 1 条或到 500 tick 时结束。

## 玩家接口

默认导出同步函数，每 tick 调用一次；通过方法登记意图，入口不返回动作：

```js
export default function tick({ game, Memory }) {
  game.self.move(game.self.heading);
}
```

- `game.self.move("up" | "right" | "down" | "left")` 登记移动一格；方法返回 undefined。
- 不调用时默认沿当前 `heading` 前进；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，所有命令收齐后同时结算。
- 入口只能返回 undefined；返回对象或 Promise 属于 ENTRYPOINT_ERROR。动作不合法（例如方向值错误）记为 INVALID_ACTION；即使自己 catch 住错误，也不能再为这个 tick 提交动作。
- game 及嵌套数据只读；旧 tick 的角色方法不能用于新 tick。

## game：当前完整公开视图

- `self`：自己的 `id`、`slot`、`body`（从头到尾的格子数组）、`head`（等于 `body[0]`）、`length`、`health`、`heading`，以及 `move` 方法。
- `opponents`：其他存活的蛇，按 slot 排列，字段同 self 但没有动作方法。
- `eliminated`：已出局玩家的 `id`、`slot`、`tick`（出局时已完成的 tick 数）与 `causes`。
- `board.width`、`board.height` 为地图边长；没有网格数组，身体与食物都是格子列表。
- `food`：地图上的食物格子，按 `y * width + x` 升序。
- `tick` 为当前输入 tick，`maxTicks` 为 500。
- `events` 是上一 tick 结算产生的公开事件，首 tick 为空：move、eat、death、food-spawn。death 的 causes 给出出局原因。
- 不提供寻路、安全方向或觅食 API；自行实现算法。全部字段和事件结构见随包 SDK.md。

## 策略提示

- 先排除必死方向：越界、移动后仍被占用的格子（所有蛇除尾节以外的身体，加上会被保留的尾节）、以及比你长或等长的对手头部下一步能到的格子。
- 对剩下的方向做洪泛填充，估算进去之后还有多少活动空间；空间小于自己长度的方向是死胡同。
- 体力低或自己不是最长时优先觅食，否则优先保留空间；食物离比你长的对手更近时不要去抢。
- 2 条等长的蛇围着同一个食物转圈会一起饿死；看到对手和你同距离时换一个目标。
- 把自己的身体当作墙来围堵更短的对手，但要给自己留出口。

## Memory 与资源

- 玩家接口 v1（发行与实际限额见 release.json）：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，均占用 32MiB 堆预算。
- 任一 tick 执行失败后重建环境，全局缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；不要把上一 tick 的观察缓存当作当前世界，每 tick 以新传入的 game 为准。
- 默认预算：源码 256KiB、每 tick CPU 20ms（首次与重建后的 tick 包含玩家模块初始化）、isolate 常驻堆 32MiB、栈 256KiB、Memory 64KiB、动作输出 1KiB；以开发包 release.json 的 `resolvedLimits` 为准。
- 抛错、超时、非法动作或超限时：该 tick 按沿当前 heading 前进处理，本次对 Memory 的修改丢弃（上次成功的 Memory 保留），下一 tick 继续调用你。默认前进不会避险：前方是墙或蛇身时照样出局。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用受限 console 输出调试日志（本地开发包可见，线上不收集）。
