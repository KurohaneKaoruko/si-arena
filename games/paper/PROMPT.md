# SI Arena：网格圈地参赛提示词

这是 SI Arena 平台的排位竞技：你的 bot 会与官方示例 bot 及其他玩家上传的 bot 对战，成绩计入排行榜。目标不是写出一份能运行的代码，而是写出尽可能强的策略——以明显强于官方示例 bot 为底线，向排行榜上游竞争。

交付物是一份可直接上传的 UTF-8 JavaScript 完整文件：在开发包项目中工作时，把最终代码写入 bot.js 并完成本地验证；在对话中直接应答时，只输出最终完整代码，不输出 Markdown 围栏或解释。

## 强度标准与验证

- 验收底线：本地对官方示例 bot 打满 20 局（`pnpm arena run --bot ./bot.js --matches 20 --seed 42`，覆盖种子 42–61），胜率不低于 80%，且没有任何 tick 执行错误；未达标必须继续改进并复测。
- 换起始种子复测（如 `--seed 1337`）确认不是种子运气；进一步可用 `--opponent` 挂自己的旧版本对弈，避免只针对官方 bot 过拟合。
- 分析败局而不是猜测：events 里的 reset、trail-cut 记录了每次重置的原因与责任方，据此定位是圈地贪心、安全余量不足还是进攻时机错误。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：命令输出本地 URL，在浏览器打开；整场自动跑完后可逐 tick 观察双方行为，再针对性修改策略。
- 在没有本地环境的对话中使用本提示词时，同样要求按下面的碰撞规则逐条推演关键场景（越界、同格、交换、自撞尾迹、被切断）确认动作合法且有竞争力后再输出。

## 对局与胜负

- 30×30 网格上的两人对抗。坐标左上为 (0,0)，右为 x+1，下为 y+1，边界不可穿越。
- 开局各有 3×3 领地，其中心格是你的出生点；两个出生点关于中线对称，种子决定你在哪一侧。
- 固定打满 500 tick，没有提前结束；双方永不淘汰，被重置也照常继续。
- 每个 tick 双方看到同一张完整地图，然后同时行动。
- 500 tick 打满后按最终领地格数排名，多者获胜，相同则并列第一。

## 核心循环：外出画尾迹，回城圈地

- 头部在领地外每移动一格，走过的格子就成为你的尾迹；在外原地停留不延长尾迹。当前位于领地外的头部格也在尾迹里。
- 带着尾迹走进任意一格自己的领地即闭合。尾迹不需要绕成环，两端接上己方领地即可。
- 闭合的判定：把你现有领地和这条尾迹当作屏障，从地图边缘按四邻接洪泛，走不到的格子全部划归给你，对手的领地也一样——哪怕对手正站在那格上，也不会因此重置他。围住就归你，对手同一 tick 是否闭合不影响结果；双方同一 tick 闭合时，唯一例外是两边都圈住的中立格，这些格子保持中立。
- 闭合结算后尾迹清空。领地不要求连通，断开的格子照常保留，任何一格己方领地都可以作为回城点。
- 领地降为 0 不会出局：你仍能移动、仍能切断对手，但本局再也无法闭合圈地，只能阻断对手扩张。
- 尾迹完全暴露：对手的目标格（这一 tick 要去的格子，停留就是原地）落到你尾迹的任何一格上，你这次外出就被重置。每次扩张都在权衡圈多少面积与能否安全回城。

## 碰撞与重置

所有命中都用行动前（上一 tick 结算后）的位置和尾迹判定：先把双方所有命中算完，再统一执行。命中的一方被重置——尾迹清空、头部回到出生点、领地全部保留；这个 tick 不移动、不闭合、不圈地，动作作废。

- 移动越界（不会自动转向）。
- 双方目标格相同，包括一方原地停留、被对方走进：双方都重置。
- 双方交换位置：双方都重置。
- 移动进入自己的尾迹（原地停在自己尾迹所在格不算）。
- 目标格落到对手的尾迹上：被重置的是尾迹的主人，踏入的一方毫发无损。这叫"切断"，也是主动进攻的基本手段。
- 本 tick 新画出的尾迹还安全，从下一 tick 起才能被切断。
- 被重置的一方落点（出生点）若与对手本 tick 的落点重合：双方都重置。

若出生点领地已被对手圈走，重置会在出生点留下一格尾迹，下一 tick 可能再次被切断。

## 玩家接口

默认导出同步函数，每 tick 调用一次；通过方法登记意图，入口不返回动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 移动一格，`game.self.idle()` 停留；方法均返回 undefined。
- 不调用默认停留；同 tick 多次调用以最后一次为准。位置和地图本 tick 不变，双方命令收齐后同时结算。
- 入口只能返回 undefined；返回对象或 Promise 属于 ENTRYPOINT_ERROR。动作不合法（例如方向值错误）记为 INVALID_ACTION；即使自己 catch 住错误，也不能再为这个 tick 提交动作。
- game 及嵌套数据只读；旧 tick 的角色方法不能用于新 tick。

## game：当前完整公开视图

- `self` 与 `opponent`：各自的 id、slot、position（当前头部坐标）、spawn（出生点）；只有 self 有动作方法。
- `board.width`、`board.height` 为 30、30；`board.territory` 与 `board.trails` 是长度 900 的数组，下标 `y * width + x`，-1 为无主/无尾迹，0、1 为所属席位。
- `tick` 为当前输入 tick，`maxTicks` 为 500。
- `events` 是上一 tick 结算产生的公开事件，首 tick 为空。包括 move、capture、trail-cut、reset；reset 的 playerId 是被重置者，causes 包含重置原因。用它清除失效的计划，不必靠猜位置推断对手被重置。
- 双方永不淘汰，位置始终有效；没有 alive 字段，也读不到随机数内部状态。
- 不提供寻路、安全方向、威胁判断或扩张策略 API；自行实现算法。全部字段和事件结构见随包 SDK.md。

## Memory 与资源

- 当前发行 paper@0.2.0、玩家接口 v2：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，均占用 32MiB 堆预算。
- 任一 tick 执行失败后重建环境，全局缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；不要把上一 tick 的观察缓存当作当前世界，每 tick 以新传入的 game 为准。
- 默认预算：源码 256KiB、每 tick CPU 20ms（首次与重建后的 tick 包含玩家模块初始化）、QuickJS 常驻堆 32MiB、栈 256KiB、Memory 64KiB、动作输出 1KiB；以开发包 release.json 的 `resolvedLimits` 为准。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，本次对 Memory 的修改丢弃（上次成功的 Memory 保留），下一 tick 继续调用你。持续出错不会出局，只会一直浪费回合。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用受限 console 输出调试日志（本地开发包可见，线上不收集）。
