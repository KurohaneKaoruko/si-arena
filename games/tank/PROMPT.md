# SI Arena：坦克对决参赛提示词

这是 SI Arena 平台的排位竞技：你的 bot 会与官方示例 bot 及其他玩家上传的 bot 进行 1v1 坦克对决，成绩计入排行榜。目标不是写出一份能运行的代码，而是写出尽可能强的策略——以明显强于官方示例 bot 为底线，向排行榜上游竞争。

交付物是一份可直接上传的 UTF-8 JavaScript 完整文件：在开发包项目中工作时，把最终代码写入 bot.js 并完成本地验证；在对话中直接应答时，只输出最终完整代码，不输出 Markdown 围栏或解释。

## 强度标准与验证

- 验收底线：本地对官方示例 bot 打满 20 局（`pnpm arena run --bot ./bot.js --matches 20 --seed 42`，覆盖种子 42–61），胜率不低于 80%，且没有任何 tick 执行错误；未达标必须继续改进并复测。批量汇总行按 `result.players` 的 `rank` 统计胜负，并列第 1 记为平局。
- 换起始种子复测（如 `--seed 1337`）确认不是种子运气；进一步可用 `--opponent` 挂自己的旧版本对弈，避免只针对官方 bot 过拟合。
- 分析败局而不是猜测：events 里的 hit 记录了每次被命中的位置与攻击者，bullets-cancelled 记录了对消，据此定位是躲避太慢、逼近路线暴露在对方炮口下，还是对峙时白白浪费炮弹。
- `pnpm arena dev --bot ./bot.js` 启动可视化调试页：命令输出本地 URL，在浏览器打开；整场自动跑完后可逐 tick 观察双方行为，再针对性修改策略。
- 在没有本地环境的对话中使用本提示词时，同样要求按下面的结算顺序逐条推演关键场景（移动阻挡、炮弹两个子步、对消、砖墙、命中与同归于尽）确认动作合法且有竞争力后再输出。

## 对局与胜负

- 固定 21×15 地图上的两人对抗。坐标左上为 (0,0)，右为 x+1，下为 y+1，下标 `y * 21 + x`，边界不可穿越。
- 地形：0 空地、1 砖墙（炮弹可打穿，打穿后变空地）、2 钢墙（不可摧毁，挡住炮弹和坦克）。地图随种子生成，关于中心格 (10,7) 点对称；两个出生点周围 3×3 开局为空地，且两出生点之间一定存在不经过钢墙的通路。
- 席位 0 出生在 (1,7) 面朝右，席位 1 出生在 (19,7) 面朝左；种子不交换席位。
- 每辆坦克 3 点生命。任一方生命降到 0 立即结束：存活者第 1 名，被击毁者第 2 名；同一 tick 双双击毁并列第 1。
- 最多 600 tick。打满时生命多者第 1 名，相同并列第 1。结果中的 `score` 是最终生命值。
- 每个 tick 双方看到同一张完整地图，然后同时行动。

## 动作

- `move(direction)`：先把炮口转向 `up`、`right`、`down`、`left`，再尝试向该方向前进一格。目标格在地图外、是砖墙、钢墙，或是对方当前所在格且对方本 tick 没有移开时，只转向不移动。
- `fire()`：沿当前朝向开火。同一辆坦克同时只能有一枚炮弹在飞，已有炮弹时本 tick 的 fire 无效、也不会转向。
- `idle()`：停留。默认动作是 idle。
- **转向必须通过 move 完成**：想朝某个方向开火，就先 move 过去（撞墙或撞到对方时只转不走），下一 tick 再 fire。

## 同时结算

一个 tick 内按以下顺序判定，全部基于本 tick 开始时的世界：

1. **转向与移动**：登记 move 的坦克先改朝向。双方目标为同一格时都不移动；双方互换位置时都不移动；一方移入对方本 tick 离开的格子时允许移动。
2. **开火**：登记 fire 且没有在飞炮弹的坦克，在自己所在格生成一枚朝向等于自己朝向的炮弹。炮弹永远不会击中自己的坦克。
3. **炮弹飞行**：炮弹每 tick 前进 2 格，分两个子步。每个子步所有炮弹同时前进一格，然后判定：
   - 两枚炮弹进入同一格，或在本子步互换了格子：两枚都消失，不再产生其他效果（压在砖墙上对消时砖墙保留）。
   - 飞出地图或进入钢墙：消失。
   - 进入砖墙：砖墙变空地，炮弹消失。
   - 进入对方坦克所在格：对方生命减 1，炮弹消失。生命已经为 0 的坦克在本 tick 清理前仍占格、仍会吸收炮弹，但生命不再减少。
4. **清理**：生命为 0 的坦克被击毁，移出地图，其在飞的炮弹立即消失。
5. tick 加 1；任一方被击毁或达到 600 tick 时结束。

几个直接推论：

- 炮弹从自己所在格出发，一 tick 飞 2 格，所以**距离 ≤ 2 的直射当 tick 必中**，对方来不及反应。
- 距离 3–4 的炮弹会在下一 tick 开始时停在对方身前 1–2 格；对方若在那个 tick 横向移开（移动先于炮弹飞行），炮弹落空。
- 两辆坦克面对面同时开火，炮弹一定在中途对消；这种对峙不会分出胜负，先离开射线、从侧面逼近到 2 格以内的一方才有机会。
- 开火后炮弹在飞的几个 tick 里你无法再开火；对着远处空放等于解除自己的武装。

## 玩家接口

默认导出同步函数，每 tick 调用一次；通过方法登记意图，入口不返回动作：

```js
export default function tick({ game, Memory }) {
  game.self.idle();
}
```

- `game.self.move("up" | "right" | "down" | "left")` 转向并前进一格，`game.self.fire()` 开火，`game.self.idle()` 停留；方法均返回 undefined。
- 不调用默认停留；同 tick 多次调用以最后一次为准。位置、朝向和地图本 tick 不变，双方命令收齐后同时结算。
- 入口只能返回 undefined；返回对象或 Promise 属于 ENTRYPOINT_ERROR。动作不合法（例如方向值错误）记为 INVALID_ACTION；即使自己 catch 住错误，也不能再为这个 tick 提交动作。
- game 及嵌套数据只读；旧 tick 的角色方法不能用于新 tick。

## game：当前完整公开视图

- `self`：自己的 `id`、`slot`、`position`、`facing`、`hp`、`bulletInFlight`（为 true 时 fire 无效），以及三个动作方法。
- `opponent`：对方的同名公开字段，没有动作方法；对方存活时为对象，否则为 `null`（本游戏任一方被击毁即结束，所以存活期间总是对象）。
- `bullets`：所有在飞炮弹，每项含 `position`、`direction`、`ownerSlot`，按发射先后排列。
- `board.width`、`board.height` 为 21、15；`board.cells` 是长度 315 的地形数组，下标 `y * width + x`，值为 0、1、2。
- `tick` 为当前输入 tick，`maxTicks` 为 600。
- `eliminated` 恒为空数组（一方被击毁时比赛结束，不再产生观察）。
- `events` 是上一 tick 结算产生的公开事件，首 tick 为空：move、fire、hit、brick-destroyed、bullets-cancelled、death。
- 不提供寻路、射线、威胁判断或躲避 API；自行实现算法。全部字段和事件结构见随包 SDK.md。

## 策略提示

- 先活下来：每 tick 检查对方炮弹是否在自己所在行或列上朝自己飞来、中间没有墙；在它到达前横向移开一格即可，移动先于炮弹飞行结算。
- 同一行或列且中间没有钢墙时，炮弹能一路打穿砖墙；但远距离射击对方看得见、躲得开，真正致命的是 2 格以内的直射，以及对方两侧都被墙堵住、无处可躲的射线。
- 面对面对峙只会不断对消，适时离开射线、绕到侧翼；绕行时避开对方炮口正前方 2 格以内的格子。
- 砖墙是掩体也是通路：把砖墙计入路径代价（例如 3 步），走到砖墙前开炮开路，但要记得开炮的那一 tick 你站在原地、且随后几 tick 不能再开火。
- 两个确定性的 bot 容易陷入互相阻挡、绕柱追逐的循环；用 Memory 记录最近的位置，发现原地踏步或绕圈时主动换路。
- 回合耗尽时按生命判胜，领先后不必冒险，但注意平局没有收益。

## Memory 与资源

- 当前发行 tank@0.1.0、玩家接口 v1：源码和 SDK 在环境创建时加载一次，成功 tick 间复用 JavaScript 环境。全局变量、闭包、Map 与 TypedArray 可跨 tick 缓存，均占用 32MiB 堆预算。
- 任一 tick 执行失败后重建环境，全局缓存和 API 模块状态清空，顶层代码重新运行；下一 tick 从上次成功的 JSON `Memory` 恢复。把恢复所需的计划与状态写进 Memory；不要把上一 tick 的观察缓存当作当前世界，每 tick 以新传入的 game 为准。
- 默认预算：源码 256KiB、每 tick CPU 20ms（首次与重建后的 tick 包含玩家模块初始化）、isolate 常驻堆 32MiB、栈 256KiB、Memory 64KiB、动作输出 1KiB；以开发包 release.json 的 `resolvedLimits` 为准。
- 抛错、超时、非法动作或超限时：该 tick 按 idle 处理，本次对 Memory 的修改丢弃（上次成功的 Memory 保留），下一 tick 继续调用你。停留不会自动躲弹：站在对方射线上不动照样挨打。

## 语言限制

不能使用 import、require、异步函数、Promise、网络、文件与 Node API；不要依赖 Date、现实时间或 Math.random。可用受限 console 输出调试日志（本地开发包可见，线上不收集）。
