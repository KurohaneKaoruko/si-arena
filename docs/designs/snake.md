# 贪吃蛇大作战

## 核心玩法

贪吃蛇大作战是独立的游戏 `snake`：2–4 条蛇同场，吃食物变长、恢复体力，撞墙、撞到任何蛇身或在头对头相撞中更短的一方死亡，**死亡即出局**。体力每 tick 下降，不吃东西会饿死。最后存活的蛇获胜。

竞技场的入场、开局者规则、同时只跑一局、排位与历史保留全部与[圈地大逃杀](royale.md)相同，只是席位为 4 个：开局者占第一席，其余席位按本游戏排位分（相同按 1v1 圈地排位分、用户 ID）从其他普通用户中选出，不足时由官方 bot 补一个席位，入场少于 2 人不能开局，服务器只保留最近 3 局。

## 地图与开局

| 项目 | 规则 |
| --- | --- |
| 人数 | 2–4 条蛇 |
| 地图 | 正方形，边长 `11 + 2 × 人数`：2 人 15、3 人 17、4 人 19 |
| 时长 | 最多 500 tick |
| 初始长度 | 3 节，三节重叠在出生格上 |
| 初始体力 | 100 |
| 出生点 | 四个角各向内缩 2 格：`(2, 2)`、`(w-3, 2)`、`(2, h-3)`、`(w-3, h-3)`；用种子 Fisher–Yates 打乱这四个出生点后，席位 0..n-1 依次取前 n 个 |
| 初始朝向 | 出生点在左半边朝 `right`，在右半边朝 `left` |
| 初始食物 | 地图中心一格，再为每条蛇在出生点沿 x、y 各向地图中心移 2 格的位置放一格 |
| 视野 | 完整地图 |

坐标左上为 `(0, 0)`，向右 x 增大，向下 y 增大。随机数使用 xorshift32，状态 `rngState` 随世界保存；种子 0 使用 `0x9e3779b9`，初始化先丢弃 4 个输出。

## 世界与观察

世界包含 `tick`、`width`、`height`、`maxTicks`、`snakes`（按席位排列，每条含 `id`、`slot`、`body`（从头到尾的格子数组，死亡后为空数组）、`heading`、`health`（存活时 1–100，死亡后为 0）、`death`（存活时为 `null`，否则为 `{ tick, causes }`））、`food`（格子数组，按下标 `y * width + x` 升序）与 `rngState`。身体中相邻两节要么相邻要么重合，重合只出现在尾部（开局重叠尚未展开的部分）；存活的蛇之间没有重合的格子，食物不在任何蛇身上。

观察只含公开事实：`tick`、`maxTicks`、`selfId`、`selfSlot`、`board: { width, height }`、`snakes`（存活的蛇，按席位，每条含 `id`、`slot`、`body`、`head`（等于 `body[0]`）、`length`、`health`、`heading`）、`eliminated`（已出局者的 `id`、`slot`、`tick`、`causes`）、`food` 与上一 tick 的公开事件 `events`。所有存活玩家在同一 tick 看到同一张地图。

## 动作

每 tick 每条存活的蛇登记一个动作：`{ type: "move", direction }`，方向为 `up`、`right`、`down`、`left`。蛇不能停留；没有登记动作、执行失败或动作不合法时，默认动作是沿当前 `heading` 前进。

## 同时结算

一个 tick 内按以下顺序判定，全部基于本 tick 开始时的世界：

1. **体力**：每条存活的蛇体力减 1。
2. **移动**：每条蛇在目标格新增一节头部，`heading` 更新为移动方向。目标格上有食物时吃掉它：体力恢复到 100，这一 tick 不去掉尾节（长度加 1）；否则去掉最后一节。多条蛇同时进入同一食物格时都算吃到，再按相撞处理。
3. **死亡判定**：对移动后的身体同时判定，原因可叠加：
   - `boundary`：目标格在地图外。
   - `starvation`：体力减 1 后为 0 且本 tick 没有吃到食物。
   - `body-collision`：头部所在格与任意一条蛇（包括自己）本 tick 移动后除头部外的任意一节重合。尾节已经在本步移走的格子可以进入。开局三节重叠时，第一次移动不算撞到自己。
   - `head-collision`：头部与另一条蛇的头部同格。长度（含本 tick 的增长）较短的一方死亡，长度相同双方都死亡。
4. **清理**：本 tick 死亡的蛇身体全部移出地图，`body` 置空，记录死亡 tick 与原因。
5. **食物生成**：若地图上的食物少于存活蛇数（至少 1），在所有空格（没有蛇身、没有食物）中按下标升序编号，用随机数 `next() % 空格数` 选一格放食物；之后再抽一个随机数，`next() % 100 < 15` 时重新编号空格，再按同样方法多放一格。第一格没有空格时整步跳过、不抽取随机数；第二格没有空格时不放置、不再抽取下标随机数。这一步在清理之后执行，即使清理后存活不超过 1 条也照常生成。只有这一步消耗随机数。
6. `tick` 加 1；存活不超过 1 条或达到 500 tick 时结束。

同一条蛇可能同时满足多个死亡原因，按 `boundary`、`starvation`、`body-collision`、`head-collision` 的固定顺序全部记录。死亡的蛇不再获得观察、不再执行代码。

## 结束与名次

- 存活不超过 1 条时立即结束，存活者第 1 名。
- 到达 500 tick 时，存活者按长度排名，长度相同并列。
- 已死亡的蛇排在所有存活者之后，死得越晚名次越好；同一 tick 死亡的并列。所有蛇同一 tick 同归于尽时全部并列第 1。
- 名次等于排在自己前面的人数加 1。结果中的 `score` 为最终长度（死亡者为 0），结束原因为 `elimination` 或 `tick-limit`。

## 公开事件

事件按席位顺序排列，类型依次为移动、进食、死亡、食物生成：

| type | 其他字段 |
| --- | --- |
| `move` | `playerId`, `from`, `to`（越界时为地图外的目标格） |
| `eat` | `playerId`, `position` |
| `death` | `playerId`, `position`（死亡时的头部格，越界时为地图外的目标格）, `causes` |
| `food-spawn` | `position` |

本 tick 开始时存活的每条蛇都产生一个 `move` 事件，包括本 tick 死亡的蛇；地图外的目标格最多超出边界一格。

## 排位与排行榜

与[圈地大逃杀](royale.md)相同：逐对 Elo，初始 1000，K 为 32，每对使用 `K / (普通参赛人数 - 1)`；排行榜按排位分排序，官方 bot 不进入排行榜，系统失败的一局不计分。

## 观察与 SDK

玩家入口 `export default function tick({ game, Memory })`，通过 `game.self.move(direction)` 登记意图。`game` 提供 `tick`、`maxTicks`、`board`、`self`（含 `id`、`slot`、`body`、`head`、`length`、`health`、`heading` 与 `move`）、`opponents`（其他存活的蛇，按席位）、`eliminated`、`food`、`events`，全部冻结只读。不提供寻路、安全方向或觅食 API。完整接口见 [snake SDK](../../games/snake/SDK.md)。

资源限额与圈地相同：每 tick 20 ms CPU，执行出错时该 tick 使用默认动作并保留上次成功的 Memory。

## 官方示例 bot

官方 bot 每 tick 对四个方向做安全判定（不越界、不进入任何蛇身、不进入比自己长或等长的对手头部能到达的格子），在安全方向中按洪泛可达面积与到最近食物的距离打分：体力低于 40 或自己不是最长时优先觅食，否则优先保留最大活动空间。它使用与普通选手相同的观察、SDK、Memory 与预算。

## 历史保留

每局完成后，删除最近 3 局以外的比赛记录和回放文件。排位分在结算时已经更新，删除记录不影响排位。
