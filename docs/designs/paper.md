# 首款游戏：网格圈地

## 核心玩法

玩家控制彩色方块，从自己的初始领地出发。离开领地后产生尾迹，安全返回自己的领地时闭合并占领围住的区域。切断对手尾迹可以淘汰对手。玩家通过扩张、防守和偷袭获胜。

游戏不包含技能、道具、经济、科技树、障碍物或复杂单位系统。

## 地图与开局

| 项目 | 规则 |
| --- | --- |
| 人数 | 固定两人 |
| 地图 | 40×30，有边界，不循环穿越 |
| 坐标 | 左上角为 `(0, 0)`，x 向右、y 向下 |
| 视野 | 双方完整地图视野 |
| 时长 | 最多 600 tick，执行与现实播放速度分离 |
| 初始领地 | 每人 3×3，共 9 格 |
| 初始头部位置 | `(5, 14)` 和 `(34, 14)`，均为初始领地中心 |
| 初始归属 | 除双方初始领地外均为中立 |
| 初始尾迹 | 双方均为空 |
| 席位分配 | 用比赛种子随机交换用户与两个出生位置的对应关系 |
| 单位与移动 | 每人一个方块，每 tick 最多移动一格 |

两个出生位置关于地图竖直中线对称。初始领地分别覆盖 `x=4..6, y=13..15` 和 `x=33..35, y=13..15`。不设置面朝方向，选择动作后直接移动。

## 世界与观察

世界包含 tick、地图尺寸、领地数组、尾迹数组、玩家位置、存活标记及随机数发生器状态。领地和尾迹分别存储，可以出现在同一格；领地被覆盖不会自动删除对手尾迹。

地图数组按 `index = y * width + x` 排列，长度为 1200。`-1` 表示无归属，`0`、`1` 表示固定玩家席位。用户 ID 与席位映射在比赛开始时固定。

```ts
type PaperPlayer = {
  id: string
  slot: 0 | 1
  alive: boolean
  position: { x: number; y: number } | null
}

type PaperState = {
  tick: number
  width: 40
  height: 30
  maxTicks: 600
  territory: number[]
  trails: number[]
  players: [PaperPlayer, PaperPlayer]
  rngState: number
}

type PaperObservation = PaperState & { selfId: string; selfSlot: 0 | 1 }
```

players 按 slot 固定顺序保存，不因淘汰删除数组项。淘汰者 alive 为 false、position 为 null，其领地和尾迹数组元素同时清除。双方的面积从 territory 计算，不另存一份可能失配的权威计数。

每个玩家获得同一结算阶段的完整观察，并附上自己的席位与公开用户 ID。观察为数据副本，不含对手源码、Memory 或日志。引擎使用整数网格，动画坐标不参与规则。

随机数统一使用 xorshift32：状态为无符号 32 位整数，依次执行 `x ^= x << 13`、`x ^= x >>> 17`、`x ^= x << 5`，结果按无符号整数保存。初始化种子必须是 0–4294967295 范围内的整数。种子为 0 时使用 `0x9e3779b9`。用初始化的首个输出最低位决定是否交换席位，保存更新后的随机数状态；圈地结算不额外使用随机数。

## 动作

```ts
type PaperAction =
  | { type: 'move'; direction: 'up' | 'right' | 'down' | 'left' }
  | { type: 'idle' }
```

玩家可以主动选择 `idle`。它表示不移动，仍可被碰撞和切断尾迹，不会因留在自己当前头部格的尾迹上而自杀。

移动方向必须属于以上枚举，不允许额外字段；返回值不符合格式时记录 `INVALID_ACTION`。执行异常、非法动作、CPU、内存及 Memory 超限统一产生 `idle`，同时丢弃当 tick 的 Memory 修改。

## 同时结算

每 tick 按以下阶段处理，所有判定均与代码执行完成顺序无关。

1. 从结算前世界为双方生成观察，收集并固定动作。
2. 计算目标位置；`idle` 的目标就是当前位置。
3. 使用结算前的头部和尾迹、双方目标位置，计算所有碰撞与尾迹命中，合并淘汰集合。
4. 同时清除淘汰者的领地、尾迹和头部；不将其全部领地赠给攻击者。
5. 移动存活者，延伸尾迹或标记回城闭合。
6. 在同一份阶段快照上独立计算双方圈地集合，同时应用领地变化。
7. 归一化存活者的尾迹，统计面积，推进 tick，判断结束并产出事件。

任何闭合只对存活者生效。玩家本 tick 被淘汰时，不能靠同 tick 回城撤销死亡或完成圈地。头部移动轨迹仅为相邻格之间的一条边，不做连续时间碰撞。

## 碰撞与尾迹攻击

| 情况 | 结果 |
| --- | --- |
| 目标超出边界 | 越界玩家淘汰，不自动转向 |
| 两个目标为同一格，包括进入停留者所在格 | 双方淘汰，不区分领地归属 |
| 两个移动者交换头部位置 | 双方淘汰 |
| 移动进入自己结算前的尾迹 | 该玩家淘汰 |
| 目标进入对手结算前的尾迹 | 尾迹所有者淘汰 |
| 双方同时切断对手尾迹 | 双方淘汰 |
| 回城与旧尾迹被切断同 tick 发生 | 切断生效，回城玩家淘汰 |
| 移动进入对手原来的头部格，而对手已经离开且不构成交换 | 仅按该格结算前的尾迹判定，不额外判头部碰撞 |
| 新生成的尾迹 | 从下一 tick 开始参与尾迹攻击；本 tick 的新头部按目标重合判定 |

碰撞集合同时计算后统一应用，不能在处理第一个淘汰者时提前清除其尾迹，使另一方免于同 tick 命中。越界移动没有有效地图目标，不产生地图内尾迹攻击。

## 尾迹与回城

存活者移动到非本人领地时，将目标格加入自己的尾迹。尾迹包含当前位于领地外的头部格。玩家在外停留时保留现有尾迹，不重复延伸。

玩家携带尾迹移动回本人领地时标记闭合。没有尾迹、只在领地内移动不触发圈地。尾迹不要求路径首尾为同一格，连接本人领地的两个位置即可闭合。

## 圈地算法与同时覆盖

对每个闭合者，以清除淘汰者之后、应用任何新圈地之前的领地为共同基准：

1. 把本人的现有领地和本次尾迹作为屏障。
2. 从地图所有非屏障边界格出发，按上、右、下、左四邻接洪泛搜索外部可达区域。
3. 将本人的现有领地、尾迹以及所有非外部可达格合并为本次占领集合。
4. 双方集合计算完成后，一次性应用归属变化。

每格的最终归属规则：

- 只有一方占领集合包含它：归该方，可覆盖对手领地。
- 双方集合都包含它：保留本次圈地前的归属；原来中立则仍中立。
- 双方集合都不包含它：保留原归属。

闭合者完成结算后清空本次尾迹，即使部分围地因同时争夺而未获得。领地不要求保持连通，断开的已占领格继续保留，任意本人领地均可作为回城位置。

## 覆盖头部与零领地

圈地覆盖对手脚下领地不会直接淘汰对手。应用所有领地变化后，对每位存活者统一处理：

- 头部在本人领地内：清空自己的尾迹。
- 头部在本人领地外且已有尾迹：保留尾迹。
- 头部在本人领地外且没有尾迹：从当前头部格建立一格尾迹，下一 tick 可被攻击。

领地归属与尾迹归属独立。覆盖对手尾迹所在格的领地不会切断尾迹，切断只由头部动作命中产生。

领地面积变为 0 不直接淘汰，玩家仍能移动与切断对手尾迹，但本局无法再通过回城闭合增加领地，只能通过淘汰对手获胜或与对手同时淘汰取得平局。

## 胜负与得分

完成一个 tick 的全部结算后依次判断：

1. 双方都淘汰：平局，名次均为 1。
2. 仅一方存活：存活者获胜，名次为 1，另一方为 2。
3. 双方存活且已完成 600 tick：比较领地面积，大者获胜，相同则平局。
4. 其他情况继续下一 tick。

结果的结束原因使用 `mutual-elimination`（双方淘汰）、`last-survivor`（仅一方存活）与 `tick-limit`（达到 tick 上限），`completedTicks` 为已完成结算次数。结果中的玩家按 slot 排列，分别记录 `id`、`rank`、`score` 与 `alive`。

局内得分为最终拥有的领地格数；淘汰者领地已清除，得分为 0。结果同时记录结束原因、完成 tick 数、面积、存活信息与名次。面积不直接累加成排位分，排位使用 [Elo](ranked.md)。

## 观赏与回放

默认按每秒 10 tick 播放，支持 0.5×、1×、2×、4×、8×、暂停与逐 tick 前进。播放速度与服务器计算速度无关。

画面区分领地、尾迹与头部，显示双方颜色、面积、tick、存活与错误标记。圈地、切断、淘汰通过确定性事件驱动动画：世界按 tick 离散跳变，头部移动与事件高亮在随后的 tick 间隔内以连续动画进度补完，进度随播放速度缩放。跳转、单步与错误跳转直接显示目标世界稳态，不重放被跳过的瞬态动画；暂停定格当前画面。当 tick 执行出错的玩家在头部位置常显警示徽标，与动画进度无关，当 tick 被淘汰者标记在前一世界位置。系统开启减少动态效果时退化为静态标记：头部不插值，事件以固定强度标记当前 tick。服务端回放包含执行错误，不包含 console 日志；本地回放包含受限日志。

规则从 `@si-arena/game-paper/rules` 导出确定性事件：`trail-cut` 记录尾迹所有者 `playerId`、攻击者 `attackerId` 和命中位置；`elimination` 记录淘汰者和全部 `causes`；`move` 记录存活者本 tick 的原位置与目标；`capture` 记录闭合者及实际新取得的格子索引 `cells`。停留不生成 move，圈地争夺未取得的格子不进入 cells，闭合即生成 capture，即使新增格子为空。

事件按尾迹攻击、淘汰、移动、圈地的阶段顺序排列，每阶段按席位顺序处理；capture.cells 按索引升序排列。淘汰原因按 `boundary`、`head-collision`、`head-swap`、`self-trail`、`trail-cut` 的固定顺序列出。同一玩家可能同时命中多个原因，不能因先发现某个原因而漏算其他人的攻击。

## 官方示例 bot

官方 bot 使用公开 SDK，执行以下可读策略：

1. 在领地内选择一个不越界的矩形扩张路线，优先靠近中立区域。
2. 使用 BFS 计算避开自身尾迹的回城路线。
3. 当对手到自身尾迹的最短距离不大于剩余回城步数加 1 时，放弃扩张并优先回城。
4. 没有安全移动时选择 `idle`。

官方 bot 不读取隐藏信息、不使用额外预算，也不保证始终获胜或永不出错。

## 资源预算

圈地的 manifest 不覆盖平台资源默认值：每人每 tick 20ms CPU、32MiB QuickJS 运行内存、64KiB Memory；源码上限 256KiB。其他游戏可独立覆盖，不与圈地共享固定限额。完整限制及失败行为见 [资源限额](../architecture/resource-limits.md)。
