# 坦克对决

## 核心玩法

坦克对决是独立的 1v1 游戏 `tank`：两辆坦克在随机生成、中心对称的砖墙迷宫里机动开火。炮弹可以打穿砖墙，钢墙不可摧毁。每辆坦克 3 点生命，先被打到 0 点的一方落败；回合耗尽时生命多者胜。

匹配、排位、练习与 Boss 规则与 1v1 圈地相同，见[排位与匹配](ranked.md)：本游戏没有竞技场，玩家主动发起匹配，系统从其他上传了兼容代码的普通用户中选对手，没有对手时与官方 bot 练习。

## 地图与开局

| 项目 | 规则 |
| --- | --- |
| 人数 | 固定 2 人 |
| 地图 | 固定 21 × 15（宽 21，高 15） |
| 时长 | 最多 600 tick |
| 出生点 | 席位 0 在 `(1, 7)` 面朝 `right`，席位 1 在 `(19, 7)` 面朝 `left`；种子不交换席位 |
| 出生保护 | 以两个出生点为中心的 3 × 3 范围开局为空地 |
| 地形 | 0 空地、1 砖墙（可摧毁）、2 钢墙（不可摧毁） |
| 生成 | 对左半边 `x ≤ 10` 的每格按下标升序抽一个随机数 `r = next() % 100`：`r < 8` 为钢墙，`r < 38` 为砖墙，其余空地；其余格子按中心对称 `(x, y) → (20 - x, 14 - y)` 复制：右半边 `x > 10` 复制左半边，中心列 `x = 10` 的下半部分 `y > 7` 复制上半部分（这些格子抽到的随机数作废），中心格 `(10, 7)` 自身对称。复制后清空两个出生区。然后在非钢墙格子上从席位 0 出生点做四邻接搜索，若到不了席位 1 出生点，则按同样方法整张重新生成（随机数继续消耗），最多 20 次；仍不连通则最后一次生成的钢墙全部改为砖墙 |
| 初始生命 | 每辆 3 点 |
| 视野 | 完整地图 |

坐标左上为 `(0, 0)`，向右 x 增大，向下 y 增大，`index = y * width + x`。随机数使用 xorshift32，状态 `rngState` 随世界保存；种子 0 使用 `0x9e3779b9`，初始化先丢弃 4 个输出。**只有初始化消耗随机数，`step` 不再读取随机数。**

## 世界与观察

世界包含 `tick`、`width`、`height`、`maxTicks`、`cells`（长度 315 的地形数组）、`tanks`（按席位：`id`、`slot`、`position`、`facing`、`hp`、`death`）、`bullets`（按发射顺序：`position`、`direction`、`owner` 席位）、`rngState`。被击毁的坦克 `position` 为 `null`、`hp` 为 0、`death` 为 `{ tick }`；由于击毁立即结束比赛，`death.tick` 总等于世界的 `tick`。存活坦克 `hp` 为 1–3、`death` 为 `null`，站在空地上，两辆不同格；炮弹只停在空地上，每辆存活坦克至多一枚，被击毁者没有炮弹；出生区始终为空地。

观察只含公开事实：`tick`、`maxTicks`、`selfId`、`selfSlot`、`board: { width, height, cells }`、`tanks`（存活者，含 `id`、`slot`、`position`、`facing`、`hp`、`bulletInFlight`）、`bullets`（含 `position`、`direction`、`ownerSlot`）、`eliminated` 与上一 tick 的公开事件 `events`。任一方被击毁即结束、终局不再产生观察，因此观察中的 `tanks` 总是两辆、`eliminated` 恒为空数组；该字段保留以与其他游戏的观察形状一致。

## 动作

每 tick 每辆存活坦克登记一个动作：

- `{ type: "move", direction }`：先把炮口转向 `up`、`right`、`down`、`left`，再尝试向该方向前进一格。
- `{ type: "fire" }`：沿当前朝向发射一枚炮弹；同一辆坦克同时只能有一枚炮弹在飞，已有炮弹时无效。
- `{ type: "idle" }`：停留。默认动作是 `idle`。

## 同时结算

一个 tick 内按以下顺序判定，全部基于本 tick 开始时的世界：

1. **转向与移动**：登记 `move` 的坦克朝向改为该方向。目标格在地图外、是砖墙或钢墙时不移动；双方目标为同一格时都不移动；双方互换位置时都不移动；目标格是对方坦克本 tick 开始时所在格，且对方本 tick 没有成功移开（停留、开火或移动被挡）时不移动，对方成功移开时允许移入。判定依次进行：先排除地图外与墙，再排除同格与互换，最后处理移入对方格的情况，三步之间没有循环依赖。无论是否移动，都产生一条 `move` 事件。
2. **开火**：登记 `fire` 且没有在飞炮弹的坦克，在**自己所在格**生成一枚朝向等于自己朝向的炮弹。炮弹不会击中自己的坦克。
3. **炮弹飞行**：炮弹每 tick 前进 2 格，分两个子步进行。每个子步所有炮弹同时前进一格，然后判定：
   - 飞出地图或进入钢墙：炮弹消失。
   - 进入砖墙：砖墙变为空地，炮弹消失。
   - 进入对方坦克所在格：对方生命减 1，炮弹消失。
   - 两枚炮弹进入同一格，或在本子步互换了格子：两枚都消失，不再判定其他效果（压在砖墙上对消时砖墙保留）。
   以上判定在同一子步内同时成立；一枚炮弹只结算一次。生命已为 0 的坦克在第 4 步清理前仍占格：第二子步进入其格子的炮弹照常消失，但生命不再减少、不产生 `hit` 事件；它自己在飞的炮弹在第二子步照常飞行，因此双方可以同一 tick 互相击毁。两个子步结束后仍在飞的炮弹保留到下一 tick。
4. **清理**：生命为 0 的坦克死亡，移出地图，其在飞的炮弹立即消失。
5. `tick` 加 1；任一方死亡或达到 600 tick 时结束。

## 结束与名次

- 任一坦克死亡时立即结束：存活者第 1 名，死者第 2 名；同一 tick 双双死亡则并列第 1。
- 到达 600 tick 时，生命多者第 1 名，少者第 2 名；相同并列第 1。
- 结果中的 `score` 为最终生命值（死亡者为 0），结束原因为 `elimination` 或 `tick-limit`。

## 公开事件

事件按转向移动、开火、命中、砖墙摧毁、炮弹对消、死亡的顺序分组排列：移动、开火、砖墙摧毁、死亡按席位；命中与对消按发生顺序（先第一子步再第二子步，同一子步按炮弹发射顺序）。`brick-destroyed` 每方每 tick 至多一条，汇总两个子步、无摧毁则不出现；`bullets-cancelled` 的 `position` 在同格对消时是相遇格，在互换格子时是先发射那枚炮弹进入的格子：

| type | 其他字段 |
| --- | --- |
| `move` | `playerId`, `from`, `to`, `facing`（`from` 与 `to` 相同表示只转向或被阻挡） |
| `fire` | `playerId`, `position`, `direction` |
| `hit` | `playerId`（被击中者）, `attackerId`, `position`, `hp`（命中后剩余生命） |
| `brick-destroyed` | `attackerId`, `cells`（本 tick 被该方炮弹摧毁的砖墙下标，升序） |
| `bullets-cancelled` | `position` |
| `death` | `playerId`, `position` |

## 排位与排行榜

与 1v1 圈地相同：两人 Elo，初始 1000，K 为 32；与官方 bot、指定对手和 Boss 的比赛是练习，不计分。

## 观察与 SDK

玩家入口 `export default function tick({ game, Memory })`，通过 `game.self.move(direction)`、`game.self.fire()`、`game.self.idle()` 登记意图。`game` 提供 `tick`、`maxTicks`、`board`、`bullets`、`self`（含 `id`、`slot`、`position`、`facing`、`hp`、`bulletInFlight` 与三个动作方法）、`opponent`（对方存活时为其公开信息，否则为 `null`）、`eliminated`、`events`，全部冻结只读。不提供寻路、射线或躲避 API。完整接口见 [tank SDK](../../games/tank/SDK.md)。

资源限额与圈地相同：每 tick 20 ms CPU，执行出错时该 tick 使用默认动作并保留上次成功的 Memory。

## 官方示例 bot

官方 bot 每 tick 先检查是否有对方炮弹在自己所在的行或列上朝自己飞来、4 格以内且中间没有墙，是则向垂直方向躲开（无处可躲且正对炮弹时开火对消）；否则若与对方同行或同列且两者之间没有钢墙，朝对方转向，在 2 格以内、中间有砖墙需要清除、或对方两侧都被挡住时开火，否则沿射线逼近；否则按把砖墙计为 3 步代价、对方炮口正前方 2 格内加价的最短路向对方逼近，走到砖墙前就开火开路，路径记在 Memory 中、只在失效或对方走远时重算。两辆确定性坦克在点对称地图上会陷入面对面不断对消、绕柱追逐或互相阻挡的循环，因此由位置顺序（按上半图钢墙数的奇偶翻转）指定其中一方离开射线、换路或绕行，对峙时若指定方无法侧移则由另一方侧移。它使用与普通选手相同的观察、SDK、Memory 与预算。
