# 炸弹人

## 核心玩法

炸弹人是独立的游戏 `bomber`：2–4 名玩家在固定的格子地图上放置定时炸弹，炸开软墙、拾取道具、把对手困进火焰。被火焰波及即出局，**死亡即出局**。后期地图从外圈开始坍塌，逼迫玩家向中心对决。最后存活的玩家获胜。

竞技场的入场、开局者规则、同时只跑一局、排位与历史保留全部与[圈地大逃杀](royale.md)相同，席位为 4 个：开局者占第一席，其余席位按本游戏排位分（相同按 1v1 圈地排位分、用户 ID）从其他普通用户中选出，不足时由官方 bot 补一个席位，入场少于 2 人不能开局，服务器只保留最近 3 局。

## 地图与开局

| 项目 | 规则 |
| --- | --- |
| 人数 | 2–4 人 |
| 地图 | 固定 15 × 13（宽 15，高 13） |
| 时长 | 最多 400 tick |
| 石柱 | x 与 y 都为奇数的格子是不可摧毁的石柱 |
| 出生点 | 四个角 `(0, 0)`、`(14, 0)`、`(0, 12)`、`(14, 12)`；用种子 Fisher–Yates 打乱全部四个角（`index` 从 3 递减到 1，`other = next() % (index + 1)`）后席位 0..n-1 依次取前 n 个；打乱在抽软墙之前进行 |
| 出生保护 | 每个角及其沿两条边各延伸 2 格（共 5 格）开局没有软墙，4 个角无论人数都保护 |
| 软墙 | 其余非石柱格子以 70% 概率放置软墙：只对左上象限（`x ≤ 7` 且 `y ≤ 6`）逐格按下标升序处理，石柱和出生保护格不抽随机数，其余格子 `next() % 100 < 70` 时放置软墙，再按 `(x, y) → (14 - x, y) → (x, 12 - y) → (14 - x, 12 - y)` 四向镜像，保证四角公平 |
| 隐藏道具 | 每面软墙在初始化时同时决定内容：放置软墙后紧接着再抽一次，`next() % 100` 小于 20 为 `fire`，小于 40 为 `bomb`，否则为空；没有放软墙的格子不抽；镜像格子复制同一结果 |
| 初始能力 | 每人同时最多 1 枚炸弹、火焰长度 2 |
| 视野 | 完整地图，但软墙里的隐藏道具不可见 |

坐标左上为 `(0, 0)`，向右 x 增大，向下 y 增大，`index = y * width + x`。随机数使用 xorshift32，状态 `rngState` 随世界保存；种子 0 使用 `0x9e3779b9`，初始化先丢弃 4 个输出。**只有初始化消耗随机数，`step` 不再读取随机数。**

## 世界与观察

世界包含 `tick`、`width`、`height`、`maxTicks`、`cells`（长度 195 的数组：0 空地、1 石柱、2 软墙、3 坍塌）、`hidden`（与 `cells` 等长，软墙里的隐藏道具：0 无、1 `fire`、2 `bomb`，其他格子为 0）、`bombs`（按放置顺序：`position`、`owner` 席位、`fuse` 剩余结算次数、`range`；放置时为 8，同一 tick 的引信阶段立即减为 7，因此保存的世界中 `fuse` 为 1–7，为 1 表示下一次结算爆炸）、`powerups`（地上的道具：`position`、`kind`）、`players`（按席位：`id`、`slot`、`position`、`bombsMax`、`fireRange`、`score`、`death`；死亡者 `position` 为 `null`、`score` 为 0）、`rngState`。世界校验同时检查：石柱恰好在奇数坐标、坍塌格恰好等于当前 tick 已坍塌的圈、隐藏道具只在软墙下、炸弹与道具各自不重叠且只在空地、活着的玩家不站在软墙、石柱、坍塌格或道具上、每人场上炸弹数不超过 `bombsMax`。

观察只含公开事实：`tick`、`maxTicks`、`selfId`、`selfSlot`、`board: { width, height, cells }`（不含 `hidden`）、`bombs`（与世界相同的 `position`、`owner`、`fuse`、`range`）、`powerups`、`players`（存活者，含 `id`、`slot`、`position`、`bombsMax`、`fireRange`、`activeBombs`、`score`）、`eliminated`、`collapse: { startTick: 300, interval: 8, nextRing, ticksToNextCollapse }`（`nextRing` 为下一个坍塌的圈编号 0–5，全部坍塌后为 `null`；`ticksToNextCollapse` 为距下一次坍塌结算的 tick 数，无坍塌时为 `null`）与上一 tick 的公开事件 `events`。

## 动作

每 tick 每名存活玩家登记一个动作：

- `{ type: "move", direction }`：向 `up`、`right`、`down`、`left` 移动一格。
- `{ type: "bomb" }`：在脚下放一枚炸弹，本 tick 不移动。
- `{ type: "idle" }`：停留。默认动作是 `idle`。

## 同时结算

一个 tick 内按以下顺序判定，全部基于本 tick 开始时的世界：

1. **移动**：目标格在地图外、是石柱、软墙、坍塌格或有炸弹时移动无效，留在原地，不产生 `move` 事件。玩家之间不互相阻挡，可以同格、可以交换位置。
2. **放炸弹**：登记 `bomb` 的玩家按席位顺序处理，若脚下没有炸弹（含本 tick 席位更小的玩家刚放下的）且自己在场上的炸弹数少于 `bombsMax`，在脚下放置 `fuse = 8`、`range` 等于自己当前火焰长度的炸弹；否则无效，不产生事件。放炸弹的玩家可以在之后的 tick 离开该格，离开后任何人都不能再进入。
3. **引信**：所有炸弹（含本 tick 刚放置的）`fuse` 减 1，`fuse` 为 0 的炸弹爆炸。火焰按本 tick 开始时的地图计算，同一 tick 被炸开的软墙仍然阻挡其他炸弹的火焰。火焰从炸弹格出发，向四个方向各延伸最多 `range` 格：遇到地图边缘或石柱停止（不含该格）；遇到软墙包含该格并停止；遇到坍塌格停止；空地、道具、玩家、其他炸弹都穿过。火焰到达的其他炸弹（含本 tick 刚放置的）在同一 tick 连锁爆炸，反复处理直到没有新的爆炸。
4. **摧毁**：火焰到达的软墙变成空地，软墙里的隐藏道具出现在该格（新道具按格子下标升序追加到 `powerups` 末尾）；火焰到达的、本 tick 之前已经在地上的道具被摧毁；每面被摧毁的软墙给炸弹主人加 1 分，多枚炸弹的火焰同时到达同一面墙时归放置顺序最靠前的那枚。
5. **火焰致死**：移动后站在火焰格上的玩家死亡（`flame`）。火焰只在爆炸的这一 tick 存在。每名死者给火焰覆盖其所在格的每枚炸弹的主人各加 10 分（同一主人的两枚炸弹都覆盖时加 20 分），自己炸死自己不加分；死者留下的炸弹仍属于原主人并照常爆炸。只有本 tick 开始时存活的玩家能得分，本 tick 死亡的玩家在清理时 `score` 归零，之前死亡的玩家不再得分。
6. **拾取**：存活玩家所在格上的道具被拾取并消失：`fire` 使火焰长度加 1（上限 8），`bomb` 使同时炸弹数加 1（上限 6）。多人同格时都获得效果。
7. **坍塌**：从第 300 个 tick 的结算开始，每 8 个 tick（tick 编号 300、308、…、340）由外向内坍塌一圈：第 k 圈是到地图边缘的最小距离等于 k 的所有格子，k 为 0–5，第 6 圈（中心 `(6, 6)`、`(7, 6)`、`(8, 6)` 三格）永不坍塌。坍塌格变为 3，上面的软墙、炸弹、道具全部消失（炸弹不爆炸），站在上面的玩家死亡（`collapse`）。
8. **清理**：本 tick 死亡的玩家移出地图（`position` 为 `null`、`score` 为 0），记录死亡 tick 与原因。
9. `tick` 加 1；存活不超过 1 人或达到 400 tick 时结束。

同一玩家可能同时满足多个死亡原因，按 `flame`、`collapse` 的固定顺序全部记录。死亡的玩家不再获得观察、不再执行代码。

## 结束与名次

- 存活不超过 1 人时立即结束，存活者第 1 名。
- 到达 400 tick 时，存活者按得分排名，得分相同并列。
- 已死亡的玩家排在所有存活者之后，死得越晚名次越好；同一 tick 死亡的并列。所有人同一 tick 同归于尽时全部并列第 1。
- 结果中的 `score` 为最终得分（摧毁软墙每面 1 分、击杀每人 10 分；死亡者为 0），结束原因为 `elimination` 或 `tick-limit`。

## 公开事件

事件按移动、放炸弹、爆炸、拾取、坍塌、死亡的顺序排列，同类按席位或放置顺序；一个 tick 最多一个 `explosion` 事件（汇总本 tick 所有爆炸的炸弹）和一个 `collapse` 事件：

| type | 其他字段 |
| --- | --- |
| `move` | `playerId`, `from`, `to` |
| `bomb-placed` | `playerId`, `position` |
| `explosion` | `bombs`（本 tick 爆炸的炸弹 `position` 与 `ownerId`）, `cells`（火焰覆盖的格子下标，升序）, `destroyed`（被摧毁的软墙下标，升序） |
| `pickup` | `playerId`, `kind`, `position` |
| `collapse` | `ring`, `cells`（本次坍塌的格子下标，升序） |
| `death` | `playerId`, `position`, `causes`, `killerIds`（火焰击中死者的炸弹主人，不含死者自己，按席位升序去重） |

## 排位与排行榜

与[圈地大逃杀](royale.md)相同：逐对 Elo，初始 1000，K 为 32，每对使用 `K / (普通参赛人数 - 1)`；排行榜按排位分排序，官方 bot 不进入排行榜，系统失败的一局不计分。

## 观察与 SDK

玩家入口 `export default function tick({ game, Memory })`，通过 `game.self.move(direction)`、`game.self.bomb()`、`game.self.idle()` 登记意图。`game` 提供 `tick`、`maxTicks`、`board`、`bombs`、`powerups`、`collapse`、`self`（含 `id`、`slot`、`position`、`bombsMax`、`fireRange`、`activeBombs`、`score` 与三个动作方法）、`opponents`、`eliminated`、`events`，全部冻结只读。不提供火焰预测、寻路或逃生 API。完整接口见 [bomber SDK](../../games/bomber/SDK.md)。

资源限额与圈地相同：每 tick 20 ms CPU，执行出错时该 tick 使用默认动作并保留上次成功的 Memory。

## 官方示例 bot

官方 bot 每 tick 由场上所有炸弹推算未来 8 个 tick 内每格的火焰时刻（含连锁），在此基础上用广度优先搜索只走“到达时不着火、且之后仍有去处”的格子；邻近软墙或对手且放弹后存在逃生路径时放炸弹；顺路拾取道具；坍塌开始后始终留在下一圈之内。它使用与普通选手相同的观察、SDK、Memory 与预算。

## 历史保留

每局完成后，删除最近 3 局以外的比赛记录和回放文件。排位分在结算时已经更新，删除记录不影响排位。
