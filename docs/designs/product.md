# 产品与参与流程

## 目标

让用户把 AI 编写的策略程序放入直观、可视化的小型多人游戏中竞技，通过胜负、排位和比赛过程比较策略表现，并根据反馈继续改进。

比赛运行的是已生成的程序。程序成绩体现规则理解、策略实现和代码质量等因素，不宣称等同于模型临场推理能力或通用能力。模型、提示词和时间预算由用户自行选择及约束。

## 玩家与选手

“玩家”是平台用户。“选手”是该用户在某个游戏中提交的最新程序。同一用户在不同游戏中的代码、排位分和局内得分互不影响。

平台为每位用户每个游戏保存一份最新代码。用户可以反复修改并替换，但不能查看或回滚平台保存的旧代码。比赛记录和回放继续保留，不等同于代码版本管理。

官方账号具有不可由普通用户设置的官方标记，显示特殊名称或徽章。每个游戏必须提供该账号的官方示例 bot，公开源码，正常参与排位。首版采用一个官方账号，不要求设置多个难度档位。

## 参与流程

用户使用用户名和密码注册登录。浏览游戏、下载开发包、查看官方 bot 和公开回放不要求登录；上传代码和主动匹配要求登录。

1. 浏览游戏页面，了解规则、胜负条件、动作接口、执行限制和错误行为。
2. 复制统一参赛提示词，下载 SDK、引擎、游戏包、官方 bot 和本地工具。
3. 在本地使用任意 AI 工具编写 JS，运行本地比赛并查看日志和回放。
4. 上传 JS。平台检查体积、编码、语法和约定的代码格式，通过后替换最新代码；不运行一场平台试跑，也不自动创建排位。
5. 用户主动点击匹配。系统在对应游戏选手池中选择对手，不要求对手在线或确认。
6. 后端执行比赛，用户查看状态、结果和可视化回放。用户离线不取消已创建的比赛。
7. 用户在本地修改代码，再上传并主动匹配。

只有主动匹配会创建新比赛。后台领取并执行显式创建的任务，可重试幂等保存与结算；主运行器丢失世界与代码快照后不透明恢复原比赛，也不能定时拉取选手开新比赛。

## 首版页面

| 页面 | 必需内容 |
| --- | --- |
| 注册与登录 | 用户名和密码注册登录、登出、修改密码 |
| 游戏列表 | 游戏简介、进入游戏的入口 |
| 游戏详情 | 规则、统一提示词、SDK 与下载入口、官方 bot 源码 |
| 我的该游戏选手 | 最新代码上传、排位分、主动匹配入口、最近比赛 |
| 游戏排行榜 | 各用户排位分、比赛数、官方标记 |
| 比赛详情 | 参与者、执行状态、名次、局内得分、排位分变化、回放 |
| 本地调试页面 | 只随本地工具启动，支持日志、错误、Memory 与资源信息 |

无需在线代码编辑器、服务端试跑、模型 API 配置或模型认证流程。网页中的代码展示以官方示例和用户自己的最新代码为主，首版不开放其他普通用户代码下载。

## 代码更新边界

开始执行比赛时，worker 一次性读取所有参赛者的最新代码，并固定用于本场比赛。之后发生的上传仅影响未来开局。

本场代码只在执行生命周期内暂存，比赛结束后释放，不写入回放或代码历史表。比赛开始后上传新代码，不重启正在进行的比赛。排位属于用户在该游戏的选手身份，不绑定历史代码版本。

游戏发行与玩家接口兼容版本分开。兼容升级继续使用现有代码；不兼容升级后旧选手保留代码、排位和比赛记录，但暂停主动与被动参赛，页面提示重新上传。代码的接口兼容标识是当前代码的一项元数据，不是历史源码版本管理。

比赛在创建时固定发行，开局时读取最新代码。排队期间若代码已换成与该发行不兼容的代码，任务失败、不计分，用户重新主动匹配；系统不恢复旧代码，也不把本场悄悄切换为其他规则。

## 非目标

- 严格模型评测、统一生成预算与模型 API 集成。
- 自动开赛、自动训练或自动改写用户代码。
- 玩家历史代码管理与回滚。
- 跨游戏总榜或共享排位分。
- 首版实时联机操控、平台试跑、插件市场和热安装远程游戏。
