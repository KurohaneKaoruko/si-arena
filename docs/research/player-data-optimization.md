# 常驻执行后的数据路径优化

本记录描述接口重构前的一轮数据路径优化，接续[常驻执行环境实施](player-execution-implementation.md)。之后的[基础动作 API](player-api-implementation.md)合并进同一尚未发布的 `paper@0.2.0` / v2，旧基准脚本依赖当时的调用接口，原始性能统计不作为当前 API 的测量。该阶段同时优化宿主数据处理与沙箱字符计数，没有改变游戏规则。

## 已实现

1. protocol 的 `cloneJson` 将严格 JSON 校验、精确字节计数与对象构造合并为一次遍历，不再生成全文中间字符串后 `JSON.parse`。保留隐藏属性、符号键、访问器、稀疏数组和循环引用的拒绝规则；共享引用展开，`__proto__` 作为普通自有字段保留，null 原型规范化为普通对象，数字 -0 规范化为 0。计数与真实 JSON 编码后的 UTF-8 字节数一致，不缩小安全边界，也没有移除引擎和沙箱各自的独立数据副本。
2. Paper 仅对已经完整校验、且已冻结的数字网格缓存规范化副本。缓存使用 WeakMap，以源数组为键，不阻止旧世界被回收；命中时仍复制数组，调用方不能改写缓存。可变数组每次重新校验，非法冻结数组不缓存，玩家身份、头部与领地/尾迹等世界不变量仍每次校验。
3. QuickJS 包装器在加载玩家代码前绑定原始字符访问函数，UTF-8 计数和日志截断无需为每个字符创建 Reflect.apply 参数数组。序列化仍在隔离沙箱内、计入玩家 CPU；JSON 约束、Memory 上限和失败锁定保持原有路径。绑定函数不受后续 String/Function 原型污染影响。

没有修改默认限额、WASM、并发度或 IPC 协议，也没有引入新依赖。

## 整局配对测量

[可复现脚本](player-data-paired-benchmark.mjs)构建互不串用 workspace 依赖的临时包图。两边都使用常驻 QuickJS 执行器，固定同一引擎、游戏发行、SDK、官方 bot、WASM 和限额；只切换上述三个实现模块，以相同 TypeScript 配置转译，并记录各模块源码摘要。

优化前的 JSON 与网格解析模块取自原始提交 `af8bab107f3d58107541b3c713027d8ecb923d8d`，与本轮修改前一致；包装器只还原原有字符访问方式，保留上一轮所有常驻执行语义。完整原始数据见 [player-data-paired.json](player-data-paired.json)。

```sh
pnpm build:packages
node docs/research/player-data-paired-benchmark.mjs --pairs 6 > /tmp/arena-data-paired.json
```

Apple M4、Node.js 26.11.1，双方官方 bot，seed 42–47。每种实现各一场完整预热不计入统计，正式采样 6 组、12 场，每场完整 600 tick。组内前后顺序交替，比赛串行运行、同场双方并行。计时包含进程启动、执行、规则、gzip 回放写入与 fsync、进程关闭；回放读取和完整重演另行计时。

| 指标 | 上一轮常驻执行 | 本轮数据优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 整局平均墙钟 | 2.833s | 2.262s | **20.15%** |
| 整局加回放读取/完整核验 | 4.426s | 3.363s | **24.02%** |
| 60KiB Memory 单次执行往返均值 | 8.298ms | 4.970ms | **40.11%** |

整局平均省 0.571 秒，速度约 1.25 倍；每组配对耗时减少 19.18%–20.90%，配对中位数为 20.45%。12 场均无执行错误，每组逐 tick 动作摘要和终态摘要完全一致，所有回放重演通过。

Memory 探针是独立场景：100 次正式采样，另 5 次预热，真实隔离进程和同一默认预算，逐 tick 读写 60KiB ASCII 字符串；数据包含 IPC、宿主处理和受限环境序列化，不能视为纯序列化的提升，也不能与整局百分比相加。

上轮常驻执行自身的 21.16% 和本轮 20.15% 来自不同轮次的对照实验，不把它们相加或据此宣称已实测累计提升。这里也未计入数据库、排队、上传校验或浏览器渲染，未在低配硬件测量，不承诺其他玩家策略的固定提升。

## 验证

`pnpm check` 通过：类型检查、lint、格式与测试均完成，387 项测试通过、35 项按环境条件跳过；保留 3 条既有 web 副作用导入 lint 警告。新增回归覆盖严格 JSON 的拒绝集合、精确字节边界、Unicode/转义/孤立代理项、原型键与 -0、共享引用展开、缓存输出独立性、可变或非法冻结网格的拒绝，以及跨 tick 污染 String/Function 原型后仍执行原有字节限制。

`pnpm test:artifacts` 通过，包含全量生产构建、6 个打包包与 12 个公开 exports、仓库外严格 NodeNext 类型、真实隔离沙箱、600 tick 比赛、CLI 批量比赛与回放、编译后 API，以及 1 个独立 ZIP 开发包的下载、初始化、冻结依赖安装、官方对手、日志和本地查看器流程。基准脚本语法检查与相关文档 29 个本地链接检查通过，正式测量记录的三个生产模块摘要与该阶段最终工作区源码一致。真实 PostgreSQL 与 Linux cgroup 检查仍依赖相应环境，本机未配置的项目按测试条件跳过。

## 后续方向

宿主仍保留多个边界上的严格复制，观察和结果仍通过 JSON IPC 传递。后续若继续优化，应重新采样真实玩家负载，衡量重复边界复制与 IPC 的剩余占比，再决定是否收拢边界或调整传输；不得直接省略输入校验、把可变世界暴露给规则/执行器，或放宽玩家资源限额。计算量主要来自策略本身时，框架优化收益会更小。
