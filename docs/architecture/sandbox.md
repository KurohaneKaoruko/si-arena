# 玩家代码沙箱

线上与本地使用同一执行组合：`@si-arena/runner` 管理每场独立 Node 进程，进程内的 `@si-arena/sandbox` 为每位玩家创建独立的 isolated-vm V8 isolate。规则引擎不依赖 Node、沙箱或具体游戏。

## 边界与生命周期

业务 worker 只领取已有比赛、读取冻结源码与发行、监督比赛进程，并在候选回放可靠保存后确认租约和结算。比赛进程不获得数据库凭据，环境变量不继承业务配置。可信游戏通过显式注册的本地公共模块入口加载，玩家源码始终是文本，不能作为宿主模块执行。

权威世界、规范动作和已提交 Memory 保存在比赛进程的协调器中，不在玩家 isolate 内。规则、观察生成和回放写入在同一进程完成，观察与 Memory 不经过逐玩家的操作系统 IPC。每 tick 所有观察来自相同世界，收齐全部规范动作后只调用一次 step。

每位玩家在本场独占常驻 isolate、Context、模块与 SDK，成功 tick 间允许全局变量、闭包和 SDK 状态作为易失缓存。每 tick 使用捕获的解析器注入新的观察和 Memory；旧引用不会修改下一 tick 的 Memory。任一玩家执行失败后仅销毁其 isolate，下一 tick 重新加载模块，只恢复上次成功的 JSON Memory。

普通 JS 异常、死循环、CPU、墙钟、isolate 堆超限与非法输出均可独立处理，不需要每玩家一个进程。V8 原生崩溃、进程 OOM 或整个比赛进程无进展属于系统失败：终止该场、不计分、不发布有效回放，不进行进程级续跑，其他比赛进程继续运行。isolate 堆限制不是整个进程的 RSS 硬上限。

## 输入、输出与性能

入口为同步默认导出函数，接收 `{ game, Memory }` 并返回 undefined。可信 SDK 工厂接收冻结观察与私有 submit/reject，定义基础动作方法并初始化默认意图。旧 tick 的动作闭包不能提交到新 tick，reject 锁定失败。观察与 SDK 的玩家可见形状保持不变，棋盘仍为普通冻结数组。

框架、SDK 和玩家模块只在环境创建时加载；可信输入解析和视图准备合并为一次 isolate 调用。协议 `snapshotJson` 创建的深冻结数据可以复用编码，共享棋盘只需编码一次；任意 Object.freeze 的对象不能自行进入可信缓存。编码不调用 getter 或 toJSON，保留严格 JSON 接受集合与字节预算。规则侧缓存仅针对已验证的不可变世界和共享观察数据，始终保留每位玩家的身份、席位、tick 与世界不变量检查。

每 tick 严格序列化候选动作与 Memory，再由协调器验证动作并原子提交。任一失败整体丢弃动作和候选 Memory，使用游戏默认动作并保留旧 Memory。普通执行不复制无人读取的 Memory 诊断；实时调试按需发送变化的已提交 Memory，追踪上限 32MiB，单条诊断仍受 IPC 帧限额约束，超限显示截断。IPC 写缓冲达到背压阈值时等待排空后再发送下一条，接收端短暂变慢不会使比赛因队列超限而失败；取消与整场无进展看门狗继续生效。Memory、源码与 JS 堆不进入回放。

玩家模块首次及重建后的编译、顶层执行、每 tick 入口、动作方法、日志与输出序列化计入该 tick CPU；可信初始化、输入注入与 SDK 工厂不计入玩家 CPU，仍受墙钟兜底。CPU 使用各 isolate 自身的 cpuTime，不用墙钟代替。每 1ms 轮询超限并销毁对应 isolate，正常输出前再次检查。

堆与调用栈的可捕获 RangeError 若被玩家捕获，属于普通 JS；未捕获时记录对应资源错误。整体堆超限直接销毁 isolate。微任务 CPU 计入同 tick，已序列化的输出不能再被修改。玩家环境没有 Node、网络或定时器，并移除 WebAssembly、SharedArrayBuffer 和 Atomics。错误与日志格式化在受限环境内完成，宿主不读取任意玩家 getter 或接收可调用对象。

## 比赛进程与回放

控制和诊断使用有界长度前缀通道，携带 executionId。源码逐玩家按 UTF-8 字节分块，以 ASCII 编码传输，避免控制字符或多人总源码超过单帧预算；比赛发行、参与者和配置在启动时固定。比赛进度与调试消息校验比赛、玩家、tick 和进程代次，迟到消息不进入新请求。外层看门狗检测整个 runner 无进展，取消会终止比赛进程。

回放在比赛进程内使用有界缓冲与压缩流背压，保存完整初始世界和连续规范动作，不保存每 tick 世界。完成时同步文件，再以不可覆盖方式创建候选路径；返回成功前已完成持久化。外层仍在单事务中确认执行权、提交终态与双方排位，重复提交不能重复计分。失败或取消只清理自身私有暂存文件。

默认整场 runnerMemoryBytes 为 512MiB，发行时至少覆盖 `maxPlayers × max(heapBytes, 8MiB) + 128MiB`。`local` 提供 isolate 限额，不承诺整个进程的 RSS 硬上限；Linux `cgroup-v2` 在创建 isolate 前限制整场进程内存、swap 和线程数，配置失败不降级。部署层继续负责低权限身份、网络、文件系统和系统调用边界。

## 校验与分发

上传与本地文件加载使用独立的短生命周期校验进程，只运行受限 AST 检查和同版 V8 模块编译，不实例化模块、不执行顶层代码、不调用入口。静态 import、动态 import、导出转发与顶层 await 均拒绝。服务端校验并发限制仍为 2，不占比赛配额。

线上和开发包共享 runner、sandbox、engine、游戏与资源发行。isolated-vm 7.0.1 的预编译二进制分发方式保持不变，不引入自有原生扩展。旧逐玩家进程执行链路已删除。具体 API、Linux 测试和性能基准见 [runner](../../packages/runner/README.md)、[sandbox](../../packages/sandbox/README.md) 与[执行架构性能记录](../research/runner-architecture-performance.md)。
